## What To Build

Create the first vertical slice of Milestone 1: a Node/TypeScript CLI that proves `web-ifc` can open the private Barclay IFC and writes a non-canonical risk-scan artifact.

The command should be:

```text
npm run ifc:inspect -- "<ifc path>"
```

It should write:

```text
outputs/{fileHash}/smoke.json
```

The smoke artifact is not canonical IFC evidence. It only proves parser access, schema detection, project unit signal discovery, relevant class counts, and sample STEP id access.

## Acceptance Criteria

- [ ] Project has a minimal Node/TypeScript scaffold.
- [ ] `web-ifc` is installed and used behind a small boundary, not scattered through the CLI.
- [ ] `.gitignore` ignores generated outputs and IFC-like files.
- [ ] CLI accepts an IFC file path argument.
- [ ] CLI computes a file hash.
- [ ] CLI detects IFC schema when available.
- [ ] CLI reports whether project length units appear available through `IfcProject` / `UnitsInContext`.
- [ ] CLI counts `IfcWall`, `IfcWallStandardCase`, `IfcSlab`, `IfcRoof`, `IfcCurtainWall`, and `IfcBuildingElementProxy`.
- [ ] CLI counts `IfcRelDefinesByType`, `IfcRelAssociatesMaterial`, `IfcRelDefinesByProperties`, `IfcMaterial`, `IfcMaterialLayerSetUsage`, `IfcMaterialLayerSet`, `IfcMaterialLayer`, `IfcMaterialConstituentSet`, `IfcMaterialList`, `IfcMaterialProfileSetUsage`, `IfcMaterialProfileSet`, and available `IfcTypeObject` subtypes if easy.
- [ ] `smoke.json` includes total count plus up to 5 STEP ids per counted class.
- [ ] `smoke.json` does not include names, GlobalIds, object types, descriptions, property values, material names, or other model evidence.
- [ ] Zero counts are treated as findings, not command failures.
- [ ] Command fails only for file read, `web-ifc` init/load/open, or output write errors.
- [ ] CLI warns if source IFC is inside the repo, but does not overbuild privacy/security.
- [ ] Private Barclay IFC remains outside the repo and uncommitted.

# Refactor Plan - Artifact Type Boundary

## Implementation

- Status: complete
- Verification: `npm test`, `npm run typecheck`, and private Barclay verifier passed.

## Problem Statement

Milestone 2 added calculation-input artifacts cleanly, but the artifact writer still imports `AssemblyReadinessDiagnostic` from the application workflow module. That import existed before Milestone 2, but it weakens the dependency map: infrastructure storage should not need application orchestration types. This is not an urgent blocker, but it is the clearest small cleanup to keep modules S-tier before the next milestone adds more artifact DTOs.

## Solution

Move artifact-facing DTO types into a small domain or application artifact contract module that both the application workflow and local-file writer can import. Keep behavior unchanged. Do not redesign artifact writing, manifest versions, or diagnostics rendering.

## Decision Document

- Keep artifact writing in infrastructure.
- Keep orchestration in application.
- Keep derived parser semantics in domain.
- Use the new artifact contract module only for shared DTO types crossing application/infrastructure.
- Do not introduce a generic serialization framework.
